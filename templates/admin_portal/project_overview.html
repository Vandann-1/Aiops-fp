End-to-End Operational Lifecycle Pipeline
1
Deterministic Ticket Normalization & Triage

Extracts structured metadata (Intent, Service, Priority) using deterministic keyword and regex heuristics. Normalizes unstructured descriptions without external LLM dependencies.

Intent: {{ intent_stats.0.intent|default:"Deterministic" }} Priority: P1–P4
2
Local NLP TF-IDF & Cosine Similarity Runbook Retrieval

Runs scikit-learn TF-IDF vectorizer over active runbook corpus. Matches incident text against runbook title, description, and indicative symptoms. Generates citation evidence metadata showing matched keywords and cited procedure steps.

Min Score: 20.00% scikit-learn TfidfVectorizer
3
Pre-Execution Safety Verification & Human Approval Gate

Generates a 7-point Diagnostic Checklist evaluating system state, active runbook status, and safe allowlist presence. IT Admin inspects dry-run simulation preview and explicitly approves or rejects.

Human-in-the-Loop Read-Only Dry Run
4
Allowlisted In-Process Safe Automation Execution

Executes approved remediation strictly via predefined Python functions in SAFE_ACTIONS allowlist. Zero operating system commands, subprocesses, subshells, exec, or eval.

14 Allowlisted Actions Simulation Mode
5
Simulated Post-Execution Verification

Verifies system health before marking ticket resolved. If verification passes, incident transitions to RESOLVED; if verification fails, ticket remains OPEN for human investigation.

Passed: {{ verifications_passed }} Failed: {{ verifications_failed }}
6
Continuous Feedback & Knowledge Base Updates

Employees submit 1–5 star ratings and comments on resolved tickets. Telemetry directs IT Admins to refine runbook procedures, adjust indicative symptoms, and update remediation actions.

Feedback Loop Active Knowledge Lifecycle
Safety Model Guarantees
  • 1. Air-Gapped Local NLP No external AI APIs, no cloud LLM services, no data exfiltration risk.
  • 2. Strict Allowlist Enforcement Only predefined functions in SAFE_ACTIONS can execute. Prohibited commands rejected unconditionally.
  • 3. Zero Shell / Subprocess Calls Pure in-process Python mocks. No os.system, subprocess, or shell injections.
  • 4. Human-in-the-Loop Gate Automation cannot execute without prior explicit IT Admin review and approval.
  • 5. Reversible Actions & Rollback Every allowlisted action documents reversibility status and predefined rollback procedures.
  • 6. Verifiable Audit Trail All approvals, executions, blocked attempts, and verifications recorded in append-only AuditLog.
